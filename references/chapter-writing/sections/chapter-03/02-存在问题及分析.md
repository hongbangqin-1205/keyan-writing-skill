# 存在问题及分析（第三章第 2 节）

与现状小节一一对应，逐领域分析存在的问题。流程：素材卡 → 动态清单确认 → 小节正文大纲 → 第一轮写全写足 → 第二轮查漏补缺。

## 关键规范

### 方面清单：与现状一一对应

问题方面的清单必须与第一节现状方面**一一对应**（现状讲"网络安全现状"，问题就有"网络安全问题"）。
以用户确认的现状清单为准，写入 outline 的 `required_items`。

### 每个问题固定结构

- 先概括总体问题，再用"（1）（2）（3）……"逐条展开具体问题；
- 每个问题**从对应现状推导**，锚定现状节的证据（缺什么、什么不达标、什么效率低）；
- 问题表述要具体，不用空泛的"有待提升""还需加强"；
- 每个问题为下一节"需求"做铺垫（问题 → 需求的前半环）。

### 链条一致性（本节核心）

问题不能凭空出现：每个问题必须能追溯到现状节的某方面（如"卫健专网承载力不足"对应现状"网络安全现状 带宽百兆"）。
现状讲到的短板，问题节必须承接；现状没讲的，不得硬造问题。

## 两轮写作要求

- 第一轮就写全写足：逐方面写问题，每个问题对应现状证据，达 item_depth 下限；
- 第二轮：检查问题是否都能追溯到现状、是否有空泛表述、是否为下一节需求做了铺垫；
  问题判断的依据用 `〔推导：依据〕` 标注，数据用 SRC 锚点。

## 完成标准（可检查）

- [ ] 问题方面与现状方面一一对应，逐项齐全
- [ ] 每个问题能追溯到对应现状证据
- [ ] 问题表述具体（缺什么/不达标/效率低），无空泛
- [ ] 为下一节需求铺垫
- [ ] 事实有锚点，分析推导有依据

## 典型表述

- 「总体来看，当前……仍处在夯台垒基、爬坡过坎的关键时期」
- 「（1）互联网医院入口不统一，缺乏流程监管……」
- 「（2）卫健专网承载力不足……带宽为百兆，难以满足视频类业务……」

具体内容必须依据实际项目资料填写。
