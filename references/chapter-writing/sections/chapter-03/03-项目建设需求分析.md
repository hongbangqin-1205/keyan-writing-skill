# 项目建设需求分析（第三章第 3 节）

从问题推导出具体建设需求。流程：素材卡 → 动态清单确认 → 小节正文大纲 → 第一轮写全写足 → 第二轮查漏补缺。

## 关键规范

### 需求方向清单：与问题一一对应

需求方向必须从第二节问题推导（问题讲"网络安全短板"，需求就有"网络安全建设需求"）。
以用户确认的问题清单为准，写入 outline 的 `required_items`。

### 每条需求固定结构

- 需求方向下用"（1）（2）（3）……"逐条陈述；
- 每条需求先引政策或问题依据（有锚点），再落到"需要建设什么 / 达到什么能力"；
- 需求要有明确的政策依据或问题来源，不凭空提需求；
- 需求表述对应下一节建设内容，为第五章技术方案做衔接。

### 必写项：本项目与已评审、建设项目之间的区别及关联

这是确定性必写项（profile `recommended_items` 已含）。逐项说明本项目与已批复/已评审/在建系统
在建设范围、功能定位上的区别与衔接关系，避免重复建设；缺资料时按 GAP 标注。

## 两轮写作要求

- 第一轮就写全写足：逐方向写需求，每条"依据 + 落到建设内容"，达 item_depth 下限；
- 第二轮：检查需求是否都能追溯到问题、是否有政策/问题依据、是否对应下一节建设内容；
  政策依据本地缺失时查知识库，命中先落盘 KB 卡再补写。

## 完成标准（可检查）

- [ ] 需求方向与问题一一对应，逐项齐全
- [ ] 每条需求"依据 + 落到建设内容"齐全
- [ ] "区别及关联"必写项完整（或 GAP）
- [ ] 事实有锚点，分析推导有依据

## 典型表述

- 「（1）国家、省市相关政策导向。……提出……」
- 「（2）助力卫生健康信息化提档升级的需求。打造……」
- 「本项目与……已评审项目在……方面存在区别，通过……实现衔接」

具体内容必须依据实际项目资料填写。
