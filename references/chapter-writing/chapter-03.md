# 第三章 项目需求分析与产出方案（章节总纲）

本章回答"**现在缺什么、需要什么、要建什么、产出什么**"，是承上启下的核心章。
逻辑主线固定为五环，且**五环必须前后对应、互相贯通**：

```text
现状（有什么） → 问题（缺什么） → 需求（要什么） → 建设内容（建什么） → 产出方案（得到什么）
```

## 动态清单（本章独有，先确认再写）

现状/问题/需求的**方面清单不是预先写死的**，不同项目方面不同。必须按以下三步动态确定：

1. **归纳**：读调研报告、建设方案目录与正文，归纳出本项目"现状方面、问题方面、需求方向"清单；
2. **确认**：用 `question` 工具向用户确认「我识别出现状方面 A/B/C/D、问题方面 X/Y/Z、需求方向 P/Q/R，是否正确、有无遗漏？」，按用户反馈增删；
3. **落盘**：把确认后的清单写入本项目 `outline.json` 的 `chapter_03` 节点：
   - `required_items`：确认后的方面清单（覆盖 profile 默认）；
   - `item_depth`：每个方面的最低正文字数（原文 ×0.8 左右，剔除表格；具体见各 section 文件的参考值）。

校验器按确认后的 `required_items` + `item_depth` 检查，缺一项报 `missing_item`、不足报 `empty_item`。

## 写作流程

```text
素材卡 → 动态清单确认 → 小节正文大纲 → 第一轮写全写足 → 第二轮查漏补缺 → 校验
```

## 小节与规范文件

| 顺序 | 小节 | 职责 | 规范文件 |
|---|---|---|---|
| 1 | 信息化现状 | 按确认方面陈述现有平台、系统、设备及成效 | `sections/chapter-03/01-信息化现状.md` |
| 2 | 存在问题及分析 | 与现状一一对应，逐领域分析问题 | `sections/chapter-03/02-存在问题及分析.md` |
| 3 | 项目建设需求分析 | 从问题推导建设需求 | `sections/chapter-03/03-项目建设需求分析.md` |
| 4 | 建设内容和规模 | 按建设方向概述建设内容与规模 | `sections/chapter-03/04-建设内容和规模.md` |
| 5 | 项目产出方案 | 概述建成后的平台、体系、能力产出 | `sections/chapter-03/05-项目产出方案.md` |

## 章节通用纪律

- **链条一致性（核心）**：问题必须从现状推导（每个问题对应现状某方面）、需求必须从问题推导、
  建设内容必须响应需求、产出必须对应建设内容；不允许现状讲 A、问题讲 B、需求讲 C 互不衔接。
- **证据**：机构数、平台数、带宽、测评等级、投资额等数字必须来自证据（SRC 本地素材）；政策文号、标准版本必查知识库；
  问题分析中的判断用 `〔推导：依据〕` 标注，不得伪装成事实。
- **锚点**：事实句 `〔SRC-007〕`/`〔KB-001〕`，分析句 `〔推导：依据〕`；发布时由 assemble 剥离。
- **两轮**：第一轮写全写足、达到 item_depth 逐项下限；第二轮只查漏补缺，记录到 `丰富记录.md`。
