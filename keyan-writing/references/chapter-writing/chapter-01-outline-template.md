# 第一章小节正文大纲模板

`大纲.md` 是素材卡之后、正文之前的必需产物。它不是目录，而是每个小节的写作蓝图。

## 使用规则

- 每个第一章小节至少一个 `##` 块；小节名称必须与 outline 的 section 对应。
- 第一轮就要写全写足：大纲列明每项必写要素及其目标篇幅（按 profile `item_depth` 逐项下限），不写"骨架稿"。
- 每个必写要素都要有证据卡、GAP 或明确的技术推导类型。
- 政策文号、标准版本、法规施行日期在大纲阶段就标注 KB 卡来源。
- 大纲要写清"第一轮已覆盖"与"第二轮可能需补的政策/标准/技术缺口"。
- 不得在大纲阶段编造项目事实或把模型推导写成已确定事实。

## 模板

```markdown
# 小节正文大纲 · chapter_01

## 项目概况

### 写作目的
本小节回答项目是什么、建设什么、如何建设、达到什么目标。

### 第一轮必写要素（逐项达到 item_depth 下限）
- 项目全称、简称、性质（≥100 字）
- 建设目标：总体定位、建设思路、服务对象、分方向目标、预期效果（≥500 字）
- 建设任务及任务与系统的对应关系（≥500 字）
- 建设地点、建设规模、工期、投资、资金来源
- 建设内容：领域概述 + 系统级概览表（≥800 字）
- 建设模式：建设主体/使用对象/部署方式 + 系统级明细表（含功能模块列，≥400 字）
- 绩效目标：成本/产出/效益/满意度四类一级指标 + 指标值表（≥600 字）

### 第一轮证据映射
- 项目全称及性质：SRC-001
- 建设目标与建设内容：SRC-001、SRC-002
- 投资与工期：SRC-001
- 建设模式系统明细：SRC-001 建设范围表
- 绩效目标：绩效表/可研终稿；缺失则记录 GAP
- 政策文号/标准版本/法规日期：KB-*（必查）

### 正文组织
1. 基本信息与项目定位
2. 总体目标与建设任务
3. 建设内容、规模和模式
4. 工期、投资、资金和绩效目标

### 表格要求（第一轮就装配）
- 建设内容概览表：领域/主要建设内容/建设性质/主要用途
- 建设模式明细表：领域/系统名称/建设模式/覆盖范围/使用对象/部署位置/功能模块
- 绩效目标表：一级指标/二级指标/三级指标/指标值（成本/产出/效益/满意度框架）
- 投资构成表：投资构成/金额/占总投资比例

### 第二轮查漏补缺
- 建设目标是否遗漏全生命周期、服务对象、应用方向和预期效果
- 建设任务是否覆盖所有实际建设领域
- 建设内容/建设模式是否下钻到系统级，功能模块列是否补齐
- 绩效目标是否用标准四类一级指标框架，指标值是否齐全
- 技术标准、等保、数据治理和部署方式是否具体
- 本地缺政策文号/标准版本/法规日期、技术方案不详时检索 KB-TECH/KB-PROJECT；最新标准或公开技术资料可检索 WEB
- 技术仍缺资料时允许 `〔推导：依据通用技术方法〕`

### 完成标准
- 第一轮所有必写要素均达到 item_depth 下限，或显式 GAP
- 绩效目标用成本/产出/效益/满意度标准框架
- 建设内容、建设模式均含系统级明细表
- 关键表格不被一句概述替代
- 事实有锚点，推导有依据，扩展资料已落盘
```

其他小节按同样结构编写，替换"必写要素、证据映射、正文组织、表格要求和第二轮查漏补缺"。
