# 第五章主清单模板

`主清单.md` 是第五章的**唯一真源销号表**，写作前用抽取脚本召回候选、agent 归一后落盘。
没有主清单不得开写，分次写靠它追进度，合并校验靠它查缺漏。

## 生成步骤

1. 跑抽取脚本召回功能点候选：
   ```bash
   python scripts/extract_checklist.py --source <建设方案.docx> --out 主清单候选.json
   ```
   输出每个功能点：`title`（表标题=系统锚）、`path`（层级路径，长度不固定）、
   `description`（功能描述）、`workload`（人月）。

2. agent 归一：把 `path` + `title` 映射到"领域→系统→模块→子模块→功能点"：
   - **领域**：预算清单所在领域（附表1=数智潍坊健康大脑，附表2=提服务，…）；
   - **系统**：`title` 是系统名时直接用；`title` 是领域名时，`path` 首列是系统（健康大脑：`path[0]`=数据中枢）；
     提服务/重整合/促协同/辅治理的 `title` 是系统名（如"（一）健康潍坊智慧服务平台"），`path` 首列是模块；
   - **模块/子模块**：`path` 中间列依次是模块→子模块（长度随系统深浅不同）；
   - **功能点**：`path` 最后一列 = 功能点名，`description` = 功能描述。

3. 落盘为销号表。

## 归一规则（层级漂移的处理）

- 不假设 path 长度固定：健康大脑功能点 path 长 5（系统/模块/子模块/子子模块/功能点），
  健康画像 path 长 3 或 4（模块/子模块[/子子模块]/功能点），提服务 path 长 4；
- 以"预算清单 + 正文语义"为准，功能点最后一级总是叶子，描述列是它的正文依据；
- 归一时不得增删功能点——预算清单一行 = 一个功能点，缺一不可。

### path → 标题层级的折叠规则（确定，不留主观裁量）

预算清单的 `path` = [系统?] [模块列...] [功能点]，中间模块列数不固定（2~4 列）。折叠到可研的
H4系统/H6模块/H7子模块/H8功能点，规则如下（**最后一列永远是 H8 功能点，倒数第二列永远是 H7 子模块**）：

| path 形态 | 系统(H4) | 模块(H6) | 子模块(H7) | 功能点(H8) |
|---|---|---|---|---|
| `[系统,模块,子模块,功能点]`（健康大脑，4列） | path[0] | path[1] | path[2] | path[3] |
| `[模块,子模块,功能点]`（健康画像 len3） | 表标题 | path[0] | path[1] | path[2] |
| `[模块,子模块,子子模块,功能点]`（健康画像 len4） | 表标题 | path[0] | path[1]·path[2]（合并） | path[3] |
| `[模块1,模块2,模块3,功能点]`（更多中间列） | 表标题 | path[0] | path[1]·path[2]·…（合并到倒数第二列） | 最后一列 |

- **"系统"在哪**：`title` 是系统名时用它做 H4；`title` 是领域名时 path[0] 是系统（健康大脑）；
- **"模块(H6)"**：取 path 的第一层模块；
- **"子模块(H7)"**：path 除最后一列（功能点）和第一层模块外的**所有中间列合并**，用"·"连接
  （例：`子模块·子子模块`），保证每个功能点都落在 H7 之下；
- **功能点(H8)**：path 最后一列，同名功能点逐行保留，靠正文区分。

这样无论预算清单中间有几层，都能确定地压到 H6/H7 两层，消除归一的主观裁量。

## 覆盖核对（抽完必须做）

- 软件开发功能点来自附表1-6（预算清单）；标准体系、安全一体化、兴产业等功能点可能在正文而非预算清单，
  agent 需从正文补齐并标来源；
- 核对功能点总数与 `depth_contract.min_function_points`，不足的说明缺哪个领域。
