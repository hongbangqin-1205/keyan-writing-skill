# 来源优先级与事实基线

可研报告的写作质量首先取决于"用哪份资料当真"。同一项目往往同时存在投标文件、
建设方案、子系统方案、调研报告和已评审的可研终稿，口径可能互相冲突。写作前必须先
确定来源优先级，并建立一份事实基线表，全文按同一口径落地。

## 一、来源优先级（高 → 低）

按内容类型分流：

- **项目事实**（现状、需求、金额、机构、建设内容）：本地正式文件优先；知识库/网络只用于本地不足时补充或版本核对，
  案例数字、姓名、地点不得未经核验直接当本项目事实。
- **政策文号、标准规范、编制依据**：**知识库必查**（政策密集章第 1、2 章以 KB- 卡为主）；本地政策/标准清单只能核验、
  不能替代；网络用于核对最新版本或补充公开资料；引用前必须落盘，不得凭模型记忆写文号与版本。
- **技术方案与系统结构**：本地建设方案、设计方案优先；不够详细时查知识库和网络；
  仍无资料时允许模型通用技术知识推导，但必须标记推导边界与适用前提。
- **同类项目口径/写法参考**：知识库案例库用于结构、表格和写法参考；案例数字、姓名、地点、投资不得直接作为本项目事实。
- **通用专业知识**：用于编制规范、方法论、技术扩展、指标组织方法，不用于编造项目事实、政策文号或标准版本。

同级冲突分别列明并标 `GAP`，不擅自取舍后隐藏另一口径。

## 二、事实基线表（写作前建立，全文统一）

把易冲突的关键口径集中登记，所有章节引用同一份基线，避免同一数字在不同章节不一致：

| 基线项 | 取值 | 依据来源 | 冲突口径 | 处理 |
|---|---|---|---|---|
| 项目全称 | … | 批复/可研终稿 | 简称/别称 | 统一全称，首次出现给简称 |
| 项目性质 | … | 批复 | 新建/升级改造混用 | 以批复为准 |
| 建设工期 | … | 批复/可研终稿 | 他处工期不同 | 以批复为准，其余标 GAP |
| 项目总投资 | … | 投资估算批复 | 他处总额不同 | 以批复为准，其余单列 GAP |
| 资金来源 | … | 批复 | 比例不明 | 缺比例标 GAP |
| 覆盖机构数 | … | 可研终稿 | 各资料数字不同 | 以可研/批复为准 |
| 建设内容/系统清单 | … | 已确认子系统方案 | 命名不一致 | 统一命名并记别名 |
| 绩效目标值 | … | 可研终稿/绩效表 | 缺量化值 | 缺值标 GAP |
| 建设地点 | … | 批复/可研终稿 | 缺详细地址 | 补地址或标 GAP |

基线表宜放在项目 `work/` 下（内部工作文件，不进交付正文）。

## 三、证据使用要求

- 正文不写来源标记（"（来源：SRC-001）"），来源记入 sidecar 与上下文记录
- 政策文号、标准编号本身是正文内容，须原样写出
- 金额单位统一"万元"，占比两位小数；金额、数量、比例只能来自证据
- 现状与规划严格区分：计划建设的系统不得写成已建成或已上线
- 无法确认的项目事实一律 `GAP: <一句话待确认事项>`，不编造、不估算、不留空

## 四、检索提示

分层检索：先精确、再相关、再语义。检索工具只负责召回候选片段并给出出处，**是否采用、如何落成正文由模型判断**。

1. **本地精确定位**（文号、标准号、机构名、金额）：`python scripts/local_search.py --sources-dir normalized --query "国办发〔2021〕18号"`，
   返回 `exact` 命中（文件名+行号+片段）。文号/标准号走这里，不靠 read 全文硬扫。
2. **本地相关召回**（主题措辞不同但相关）：同脚本不带 `--exact-only`，`bm25` 跨所有 `normalized/*.txt` 返回 top-k 相关段落。
3. **原始材料检索**（第二轮查细节）：具体细节常在原文件里但没进 `normalized/` 池，用
   `python scripts/local_search.py --sources-dir extracted --query "..."` 在全量抽取文本里找回相关段落。
4. **知识库语义检索**：政策原文、标准版本、法规施行日期、本项目历史可研 → `consulting-kb-retrieval`（选库路由见其 `wiki/README.md`）。
5. **网络检索**：用户授权或 outline 开启后，查最新政策/标准/公开技术资料，WEB 命中记录 URL、日期和快照。
6. 命中"目录页/导语页"或只返回章节标题时，换更具体的措辞或加关键词重试。
7. 技术资料本地与知识库/网络都不足时，可用模型通用知识做设计推导并标记。

**选用原则**：本地已有且足够直接使用；政策文号、标准版本、法规施行日期必查知识库；技术方案本地优先、不足再查知识库/网络；
检索返回的候选片段是"待核实的候选"，不是"结论"，采纳前须确认片段确属本项目且口径一致。
